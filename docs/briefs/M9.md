## 3. Product rules (PRD §18)

- **HB-172 / HB-T-075** On a world that has Haugbui data, store a global key `haugbui <schema>` and
  `haugbui_tombs <count>` (the number of tomb ZDOs recorded, not servant slots). Same write path as servant slots.
- **HB-173** On load, scan ZDOs for tombs and compare with the recorded count. If the marker exists and fewer tombs
  are found, show one prominent popup: what is missing and that a backup can be copied back. No popup on a clean
  world, and no popup just because a zone is unloaded — count only what a full ZDO scan can see, and say so in the
  report if unloaded tombs would false-alarm. Pick the safest scan (prefer the ZDO list over loaded objects). If you
  choose, record it in PRD §23 as **to confirm**.
- **HB-T-076** (P2, opt-in). Config default **OFF**. When on, and the world has Haugbui data, copy the world folder
  once per session to a timestamped folder next to the saves. Worlds in 1.0 are folders
  (`%USERPROFILE%\AppData\LocalLow\IronGate\Valheim\worlds_local\<name>\`). Verify the path API in the 1.0.20
  decompile. The copy must be restorable by copying it back over the world folder. Do not block loading: async, and
  do not stall the main thread past about 1 s. Never copy while a save is writing.
- **HB-175 / HB-T-077** On load, validate tomb blobs, station jobs and delivery ledgers. A corrupt or future-schema
  blob disables that object's feature, logs the repair, and **does not overwrite the saved bytes**. Clamp invalid
  states you can fix (level recomputed from upgrades, reservations cleared because they are not persisted). Load
  never throws.
- **HB-174 / HB-T-078** Run the missing-mod case for every structure, plus a tomb that has items, a delivery request
  and a station job. Document a table of what survives in the README and in `TECHNICAL_FEASIBILITY.md` §9.3. The
  table must match what you observed, not what the plan hoped.
- **HB-134 / HB-T-079** A scripted self-test: transfers, a death, a production job and a delivery, with forced saves,
  then totals compared through the ledger. Zero items created, lost or duplicated. A real process kill and a real
  quit are the one manual step (see §7). Cooldown and job progress must still be there after the in-process reload
  the suite can do.
- Item safety (AGENTS.md, HB-045/061) is unchanged. No recipe crafting (HB-122).

Any choice the PRD does not answer: pick the safest option, add a PRD §23 row marked **to confirm**, and tell Kelvin.
